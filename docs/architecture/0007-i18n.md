# ADR 0007: English and Urdu

- **Status:** Accepted
- **Recorded:** 26 October 2026 (decided in Phase 4)

## Context

Section 7.4: the public site is in English and Urdu, Urdu is right to left, and Urdu needs a
font suited to its script. Public strings and the admin navigation labels come from message
files. Content entries exist per language, and a missing Urdu version falls back to English
with a notice. Section 9 requires public pages to be cached with revalidation.

## Decision

- **Routing.** next-intl with `localePrefix: "always"`: every public URL starts with `/en` or
  `/ur` (`i18n/routing.ts`). `proxy.ts` sends a bare path to the right locale. The request
  config loads `messages/<locale>.json` and fixes the time zone to Asia/Karachi
  (`i18n/request.ts`).
- **Direction:**
  - `<html lang dir>` is set per locale (`directionOf`).
  - Layouts use logical CSS properties (`ms-`, `ps-`, `start-`), so one stylesheet serves
    both directions.
  - Codes, emails, phone numbers and other Latin data are isolated as left-to-right inside
    Urdu text.
- **Fonts** (`lib/fonts.ts`):
  - English uses Inter.
  - Urdu uses Noto Nastaliq Urdu with display `swap`, and a taller line height for Urdu
    (`app/globals.css`).
  - The Urdu font is about 230 KB, so it is not preloaded: English pages never download it,
    and Urdu pages fetch it as soon as Urdu text is laid out (Phase 7).
- **Messages:**
  - All public strings, form errors and the admin navigation labels are in the two message
    files.
  - Zod error codes map to translated messages, so the same schema validates in both
    languages.
  - A unit test checks that both files have the same keys and placeholders, with no empty
    values.
- **Content:**
  - Content entries and events carry a locale, or localised fields (decision 6).
  - When the Urdu version is missing, the English one is shown with a notice, marked
    `lang="en" dir="ltr"`.
- **Caching:**
  - Public pages are statically generated per locale with five-minute revalidation.
  - Publishing content or events revalidates the whole public site (`lib/revalidate-site.ts`).
  - Canonical and hreflang links are absolute (`SITE_URL`), with English as `x-default`.
- **Admin in English.** Admin screens other than the navigation stay in English (section 7.4
  names public strings and navigation labels only).

## Consequences

- **Performance.** English pages score 97–99 in Lighthouse mobile performance. Urdu pages
  score lower (74–87, measured 26 October 2026) because the Nastaliq font is large, and its
  swap shifts right-aligned text. `docs/ACCEPTANCE.md` lists the options: a lighter Naskh face,
  `font-display: optional`, or a subset font.
- **Translations in review.** Adding a string means adding it to both files, or the test
  fails.
- **Exports.** PDFs use the standard PDF fonts, so Urdu text in a PDF prints as "?" (ADR
  0009). The screens and CSV exports show it in full.

## Evidence

- `tests/unit/messages.test.ts`.
- `e2e/accessibility.spec.ts`: axe in both languages and both themes.
- `tests/integration/content.test.ts`: the fallback and drafts hidden until published.
