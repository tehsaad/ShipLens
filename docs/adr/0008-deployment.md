# ADR 0008: Build and deployment

- **Status:** Accepted
- **Recorded:** 26 October 2026 (decided in Phases 0, 1 and 6)

## Context

Section 12 asks for:

- a multi-stage Dockerfile with a non-root user, a health check and an image under 300 MB;
- docker-compose for local development;
- CI on every push and pull request;
- deployment to Render on push to `main` after CI passes, through a deploy hook;
- migrations run at container start;
- secrets kept only in Render's environment.

The project runs on Render's free plan.

## Decision

- **Image** (`Dockerfile`):
  - Three stages: dependencies, build and runtime.
  - The runtime stage holds the Next.js standalone server, static assets, the SQL migrations,
    `scripts/migrate.mjs` and the bundled seed script.
  - It runs as a non-root user, with a health check on `/api/health`.
  - It holds no Prisma CLI: `migrate.mjs` applies Prisma's migration files with plain `pg`,
    under an advisory lock, keeping Prisma's history table.
  - Size measured in CI: 213 MB.
- **Container start** (`scripts/docker-entrypoint.sh`):
  - Apply migrations; any failure stops the container.
  - Load missing sample data while `SEED_DEMO_PASSWORD` is set.
  - Then start the server.
- **CI** (`.github/workflows/ci.yml`), on every push and pull request:
  - audit (fails on high or critical advisories in production dependencies);
  - Prisma validate, format, lint, typecheck;
  - the start-up scripts against an empty database;
  - unit and integration tests with the 60% coverage gate;
  - production build;
  - Playwright (role refusals, the report cycle, axe);
  - Docker image build, size check and a smoke start against an empty database.
- **Deploy** (`.github/workflows/deploy.yml`): when CI succeeds on a push to `main`, the Deploy
  workflow calls the Render deploy hook with `ref=<commit>`. Render then builds exactly the
  commit CI tested.
  - Deploys never overlap or cancel one another.
  - The workflow has no repository permissions.
  - The hook URL is the `RENDER_DEPLOY_HOOK_URL` repository secret.
- **Render**:
  - A Docker web service and a managed PostgreSQL 16 database, in Singapore (`render.yaml`).
  - `AUTH_SECRET` is generated by Render, and `DATABASE_URL` comes from the database.
  - The client IP is read from `CF-Connecting-IP` (`TRUSTED_CLIENT_IP_HEADER`).
  - Render waits for `/api/health` to answer 200 before it switches traffic.

## Consequences

- **Switch-over.** Until the hook secret is set, Render's own "deploy after checks pass"
  setting keeps deploying `main`, and the Deploy workflow only warns. Once a hook deploy is
  confirmed, Render's auto-deploy is turned off so each commit deploys once
  (`docs/handover.md`).
- **Migrations go forward only.** A rollback in Render does not undo a migration, so a
  migration that is not backward compatible needs a follow-up migration.
- **Free plan.** The free web service sleeps when idle, so the first request after a pause is
  slow, and a free database is kept only for a limited time.
- **Single instance.** The rate limiter keeps its counters in memory (`docs/security.md`).

## Evidence

- CI runs on every pull request and on `main`.
- The Docker smoke step in CI starts the real image against an empty database.
- `docs/handover.md` covers deployment, rollback and the runbook.
